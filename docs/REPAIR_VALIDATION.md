## 已实施范围

- R0：增加可控窗口状态事务、候选替身、独立 Win32 桌面窗口和 Python 首帧回归。新 Python 首帧用例在原版 DLL 上失败，修复库通过；历史失败报告保留。
- R1：同窗口共享临时状态租约；实际修改时快照、按位恢复、原 layered 属性安全读取、失败回滚、用户意图观察和恢复错误传播。窗口生命周期属性与 PID/线程/进程创建时间共同校验，失效代次不能修改新窗口。
- R2：候选独立试用/清理、按真实单样本耗时排序、正式激活重验及失败后尝试下一名；固定方式直接验证。正式首帧独立拥有、保留原时间，在交付前复验来源/布局/几何/会话。GDI 拒绝逻辑最小化。
- R3：冻结新增 C 符号 `MaaWSManagerCreateWithPolicy`、`MaaWSFrameGetSampleInfo`，新增独立策略/元数据结构及功能位，旧 C 结构不变。显式 FramePool 缓存仅在无更新时回退，保留采样时间/序号；来源/裁剪/尺寸/设备/会话失效后拒绝缓存。到帧刷新在原 MTA 工作线程执行，避免一次点击在延迟请求前进入队列后被丢失。六语言绑定探测新功能，旧库拒绝策略。
- 基础批次的内部诊断包含候选耗时/单样本标记、失败码、租约转换与恢复错误；后续可选增强的实施与验证见下方记录。公开诊断查询 API 继续单独设计。

C++ 类布局改变，须成套重新编译；C ABI 仍为 2。具体契约见 [集成说明](INTEGRATION.md)。

## 焦点时序补测与判据复评

曾有一次完整桌面测试在共享租约用例失败；原日志没有前台 HWND/输入时间戳，无法追溯归因。
用户不能确认当时切换到哪个窗口，并在本次补测期间保持不切窗。

新增 `--focus-cycles` 对照模式，逐阶段记录自有窗口的前台 HWND、LASTINPUTINFO 时间、样式与最小化状态；
不记录窗口标题或输入内容。Windows 最小化后的短暂空前台需重试等待，焦点控制不可用会明确失败，不能算通过。
只操作测试进程自己的目标/两个对照窗口。

| 对照 | 结果 |
| --- | --- |
| 临时收紧判据（目标前台且输入时间变化） | 双屏各 30 轮无切换/切其他窗口/程序激活目标/独立宿主线程，共 240 轮，无样式残留、无输入变化 |
| 原判据隔离构建，同一套对照 | 同样 240 轮无失败、无输入变化；程序激活目标后 60/60 保留还原状态 |
| 原判据，加入原 `SW_MINIMIZE` 时序 | 双屏每类 60 轮：无切换、原最小化时序、其他自有窗口、程序激活目标、独立宿主线程，共 600 轮；无失败，所有记录输入时间相同；程序激活目标后 120/120 保留还原状态 |

补测没有复现“库自身恢复造成前台变化而误取消意图”。仅凭旧失败不足以收紧判据；
要求新键鼠输入还会排除外部程序主动恢复并激活目标的既有行为，因此已撤回临时收紧。
最终保留恢复后前台快照与输入观察：目标后来变为前台，或目标仍在前台且出现新输入时协调恢复。
真实用户切回目标可能使测试的最终最小化断言失效；切到其他窗口的对照没有复现。
这说明历史失败存在外部焦点干扰的可能，不能断言就是用户切窗，也不能据此认定库有时序缺陷。

最终保留原判据后，完整 CTest 连续三次通过（桌面分别 35.40、35.79、35.53 秒），
Python 3.12/3.13 各 13 项通过；关闭 FramePool 的完整 CTest 3/3 通过（桌面 13.70 秒）。
结果在 `build-enhancements/final-repeat.log` 与 `build-enhancements-no-framepool/final-tests.log`。

日志：`build-enhancements/focus-tightened.log`、`build-focus-old/focus.log`、
`build-focus-old/exact-minimize.log` 及各自 CSV。隔离旧判据构建不覆盖主构建产物。
